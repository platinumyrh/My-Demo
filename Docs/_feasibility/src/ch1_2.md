# 第 1 章 引言

## 1.1 编写目的

本报告是"多人在线FPS对战系统"课程设计项目的事前可行性研究报告。

> 截至本报告编写时，项目尚未进入开发阶段；报告只做事前论证与规划，不记录开发成果。

报告的目的是在投入开发工时之前，从四个维度判断本项目能否立项、是否存在无法回避的障碍，并给出风险对策与降级预案。

- 技术可行性：判断引擎、传输层与同步方案是否成熟可落地，性能与带宽是否留有余量，能力缺口能否按计划补齐。
- 经济可行性：项目无资金投入与商业收入，故不以货币度量，而以投入工时（人时）为成本口径、以可复用资产节省的工时与能力收益为效益。
- 社会可行性：判断软件许可、素材授权、内容合规与数据隐私有无障碍，校园环境与用户接受度能否支撑本项目。
- 操作可行性：判断使用门槛、部署难度、运维成本与 5 人团队的协作方式是否可行。

本报告的读者对象见下表。

| 读者对象 | 关注重点 |
|---|---|
| 指导教师 | 选题价值，方案合理性与范围，进度是否可控 |
| 评审组 | 四维可行性的结论及依据，风险与对策是否成立 |
| 课设小组 | 技术选型，里程碑与人时分配，自测闸门与协作规范 |

报告范围覆盖项目背景与现状问题、拟建系统的定位与范围边界、四维可行性论证、风险与对策及结论；详细设计与源代码说明不在范围内。

# 第 2 章 现行组织系统概况

## 2.1 组织目标和战略

课设小组由 5 名成员组成，拟模拟小型独立游戏团队运作，按客户端、服务端、工具链与测试划分职能，实行里程碑驱动与看板管理，不设公司化组织。

| 层面 | 内容 |
|---|---|
| 小组定位 | 5 人小组，模拟小型独立游戏团队运作，按职能分工、里程碑驱动 |
| 交付目标 | 16 周内交付可联机 Demo，达到俯视角、单房 4 人、15 Hz 逻辑帧的确定性帧同步 |
| 沉淀目标 | 形成可复用的确定性帧同步框架、联机骨架、资源热更与自测工具链 |
| 核心战略 | 先闭环后丰富，以"能联机"为核心差异化 |

战略上遵循"先闭环后丰富"：第一阶段只求打通最小可玩闭环，把登录、房间与开战跑通，再依次补充战斗表现、资源热更与编辑器工具，新增需求一律让位于闭环交付。小组不与商业作品比拼画面与内容量，而以"能联机"为核心区分点。

## 2.2 业务概况

立项之前，小组的业务经验集中在单机领域：做过的项目均为单机小游戏，不涉及网络传输与服务端程序。网络方向属于空白：团队没有 UDP 传输与自研服务端的开发经验，也没有处理丢包、乱序与延迟的经历。

| 维度 | 立项前现状 |
|---|---|
| 网络能力 | 无 UDP 传输与自研服务端开发经验 |
| 质量保障 | 无自动化测试，验证依赖人工试玩 |
| 美术资源 | 依赖开放授权素材，无自有美术产能 |
| 资源管理 | 资源随包发布，无版本化与热更机制 |
| 已有基础 | C# 与 Unity 使用经验；Input System 与 Cinemachine 使用经验；自有开发机 |

质量与资源方面同样存在缺口：验证依赖人工试玩；素材依赖开放素材，不具备自有美术产能；资源随包发布，没有版本化与热更机制。已有家底亦需列出：C# 与 Unity 使用经验可支撑基础游戏逻辑开发，Input System 与 Cinemachine 使用经验可支撑角色操作与相机跟随，成员自有开发机满足开发与调试需要。这些基础不等于网络与确定性能力已经具备。

## 2.3 存在的主要问题

综合上述盘点，立项前主要面临五个问题。

1. 联机方案选型风险高。第一代状态同步、第二代确定性帧同步与采购商业方案，在确定性、带宽、学习成本与开发人时上差异显著。若立项前不做对比论证就仓促定案，一旦方案与团队能力或演示环境不匹配，返工代价将落在 16 周周期上。
2. 无确定性保证。移动积分、碰撞互推与命中判定都依赖数值运算，若逻辑层沿用浮点运算，跨平台与跨 CPU 的浮点差异会使各端结果逐步漂移，造成位置撕裂与判定不一致。不解决则帧同步方案从根上不成立。
3. 无资源热更与版本管理。资源随包发布，任何调整都需重新出包，既无增量比对手段，也无版本记录，多人协作时无法确认各端资源是否一致。不解决则测试与演示中的资源差异极易被误判为同步缺陷。
4. 无自动化测试。此前验证依赖人工试玩，而确定性缺陷往往只在特定帧序列或指令组合下出现，人工试玩难以稳定复现，更无法逐帧比对。缺少自测闸门，问题只能在后期的联机集成阶段集中暴露，压缩了修复窗口。
5. 约束硬：周期短、人力有限、无公网服务器。团队仅 5 人、周期 16 周、基准 800 人时，成员还需承担其他课程任务；演示只能依托校内局域网或本机回环。若范围不冻结、里程碑不设闸门，进度风险将累积，可能连最小联机闭环都无法演示。

五个问题彼此牵连：选型决定技术投入方向，确定性依赖网络与工具链能力，能力补齐又受周期与人力约束。因此，在投入 800 人时之前，有必要从技术、经济、社会与操作四个维度做事前可行性论证，明确范围边界、里程碑闸门与降级预案，再决定立项。
